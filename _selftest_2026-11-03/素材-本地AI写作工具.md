# 素材：为什么本地写作 Agent 值得一试

背景：很多人用网页 Chat 写公众号，来回复制、丢上下文、风格飘。
痛点：
- 素材散落在备忘录/飞书，粘贴进对话容易丢结构
- 同一账号多风格（白话/硬核）切换靠口头说，不稳定
- 想留「可复跑」的草稿与大纲，网页会话不好归档

可验证事实（自测用，勿编造外部数据）：
- 本仓库 CLI 支持 `--file` 读本地 md/txt
- 可配 `--style` 指向本地风格包目录
- 无 Key 时走固定结果；有 Key 走真实模型

希望成稿角度：给独立作者/小团队——从「复制粘贴聊天」换成「素材文件进 CLI 出 Markdown」的一次具体切换建议；少鸡汤，多步骤。
