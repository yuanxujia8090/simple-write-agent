# 把素材塞进命令行：本地写作 Agent 的一次具体切换

## 先说结论

如果你写公众号的流程还是「打开网页 Chat → 粘贴素材 → 聊几轮 → 复制回编辑器」，最值得改的不是提示词，而是素材的入口。把素材存成本地 `.md` 或 `.txt`，用命令行参数直接喂给写作工具，能一次解决三件事：素材结构不丢、同一批素材可以复跑、成稿有固定的落盘位置。

这篇不讲理念，只讲怎么换、换完看到什么、以及换不动时怎么判断卡在哪。

## 网页 Chat 写作的三个具体损耗

**第一，素材散落，粘贴时结构丢失。** 素材常在备忘录、飞书文档、聊天记录里。复制到对话框，标题层级、列表、代码块经常被压平；模型看到的是一段没有边界的文字，于是它开始猜哪句是观点、哪句是引文。

**第二，风格靠口头约定，每轮都在重新对齐。** 同一个账号可能要写白话科普，也要写硬核实测。过去的方式是每次加一句「今天硬一点」，但这句约束会随对话变长而衰减，也不可复用。

**第三，草稿不可归档，无法复跑。** 网页会话是孤立的。想拿同一批素材再生成一版，只能重新粘贴；想对比两版差异，只能靠记忆。

## 换成什么：素材文件直接进 CLI

这个仓库的 CLI 已经支持 `--file`，读取本地 Markdown 或纯文本素材。最小用法：

```bash
npm install
npm run dev -- --file ./notes.md --topic "跨端状态同步为什么总翻车" --fast
```

几个已经实现、可以直接依赖的行为：

- `--file` 可以重复指定，多份素材一起进。
- `--fast` 是快速模式，只保留论点和终稿两个确认点；在非交互运行下会自动批准，一路跑到导出。
- 不带 `--file` 也不带 `--topic` 时，命令只打印启动检查，不创建会话、不写库。想确认环境先跑这一下。
- 想固定输出位置，可以加 `--output-dir`；或者用 `--cwd` 指定工作目录，默认会从当前目录向上找 `.writing-agent` 标记。

不配 API Key 也能跑通全流程：这时走固定结果（不联网），用来验收「素材 → 主稿」这条链路是否通。配好密钥后走真实模型，参数不变。这个设计的意义很实际——管道问题不要和模型问题混在一起排查。

## 一次运行会看到什么

命令会先打印启动检查，包含工作目录、配置文件路径、模型与密钥状态、搜索配置；指定了素材和话题，会额外列出素材文件、话题、风格包入口和模式。

跑完之后会输出一组路径：

- 大纲
- 主稿
- 导出（Markdown）
- HTML（同源导出；失败时会单独标注失败原因）

这组路径就是可复跑的基础。同一批素材、同一套参数，再跑一次会得到新会话，但旧产物还在原地，可以并排比较。

## 建议的落地步骤

1. **先做素材净化。** 把要用的素材整理成一份 `.md`，保留标题和列表，删掉「待补充」「问问同事」这类给自己看的备注。素材里的噪音会被模型当成内容。
2. **先跑一次不带素材的启动检查。** 确认配置文件、密钥状态、搜索配置是你以为的那样。
3. **用小素材跑一次完整链路。** 一份短素材 + `--fast`，看四个路径是否都生成。这一步是验证管道，不是验证文笔。
4. **再换真素材、真话题。** 这时候模型输出的质量才值得评价。
5. **把命令写进笔记或脚本。** 同一栏目固定一套参数，避免每次靠回忆拼命令行。

一个容易忽略的细节：素材进 CLI 只是「输入可控」，不等于「输出一定好」。素材本身没有论点、只有一堆事实时，大纲阶段还是会空转。素材文件的写法值得单独练一次——把结论句写进素材，比在提示词里反复强调有效。

## 素材文件本身怎么写

工具只负责读，不负责整理。素材的写法直接决定大纲质量。一个够用的结构：

```markdown
# 主题

## 已确认事实
- 有出处的结论，一行一条

## 我的判断
- 我认为这意味着什么

## 不要写进去的
- 待核实、待补充、别人的原话草稿
```

三段的区别在于「谁负责」。事实段由你负责准确，判断段由你负责立场，第三段是给自己看的施工区，不该进模型视野。很多人把三段混成一段，然后抱怨模型抓不到重点——问题在输入，不在模型。

如果素材里有多份来源，建议按来源分文件，用多个 `--file` 传入，而不是手工拼成一份。来源边界在文件边界上最清楚。

## 常见卡点

- **命令只打印启动检查就退出。** 说明既没给 `--file` 也没给 `--topic`，这是设计行为，不是报错。
- **提示找不到工作目录。** 用 `--cwd` 显式指定，或确保当前目录链条上有 `.writing-agent` 标记。首次正式运行时工具会写入目录身份。
- **导出位置不对。** `--output-dir` 传绝对路径就直接用，传相对路径则相对工作目录解析。
- **想知道每一步发生了什么。** 加 `--debug` 输出调试日志，比反复猜快。
- **主题想固定。** 可以用 `--theme` 指定主题 JSON，适合同一栏目反复产出。

## 边界

- `--file` 只读 `.txt` 和 `.md`，不是万能解析器。PDF、网页、图片需要你先转成文本。
- 无 Key 时是固定结果，用于验收链路，不代表模型能力。
- 本仓库的全局命令 `writing-agent` 需要 `npm link` 或全局安装构建产物；不改全局环境时，用 `npm run dev --` 或 `node dist/cli.js` 更稳妥。

## 收尾

这次切换的成本很低：整理一份素材文件、记住一条命令。收益是可归档、可复跑、可对比。对独立作者和小团队来说，这比继续调提示词的边际收益高。
