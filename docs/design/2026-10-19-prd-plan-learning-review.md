## 结论

原 PRD 仍是有效的写作产品需求基线，已定义核心流程、主要交互、数据生命周期和本地运行边界。它需要补上项目负责人学习目标和总设计原则，避免把“做出功能”误当成“掌握 Agent 工程”。实施计划需要从按组件铺开的任务清单，补成分阶段的可运行闭环；同时统一 PRD 已列出的命令，并补足生产验证与学习验收。

本次没有证据表明需要更换 TypeScript、LangGraph、Vercel AI SDK、SQLite 或终端界面的既有选择。是否需要这些技术应由最小运行闭环和实测结果持续验证，而不是因为名词已写进设计就视作已证明。

## 多角度审查

### 需求与产品边界

PRD 已覆盖单人本地写作、访谈、研究、确认、恢复、事实规则、Markdown/HTML 导出和明确的非目标。它也有不少详细实现约束，需求层与设计层略有混合；本轮保留既有可验收行为，不做大规模拆章，以免丢失历史确认语义。新增学习目标明确标为非产品功能。

### Agent 必要性与自主度

写作产品主流程是有序阶段，适合确定性工作流；模型只应在简报理解、研究候选、论点和写作等局部任务处理不确定性。这个判断比“整个产品就是一个 Agent”更准确，也与现有阶段图及人工确认一致。程序控制身份、权限、预算、写入、状态、停止和完成验收；模型提出候选或允许范围内的行动。

### 状态、恢复与副作用

PRD 已规定检查点与产出版本分离、拒绝保留成果、外部编辑检测及确认指纹。还需在实施验证中明确覆盖执行端的副作用重试、超时后的结果不确定、版本化输入和恢复后避免重复动作。计划已加入恢复学习产出和故障演练要求；实际持久化细节继续由现有 ADR 和技术设计承载。

### 安全与隐私

PRD 有本地素材边界、凭据存储要求及事实来源规则，但生产验收需要把提示注入、工具权限和 Trace 隐私变成明确演练场景。不能把提示词约束当作权限边界，也不能让模型自报动作已完成。本次计划补入越权拒绝、密钥不进入执行记录等检查。

### 评测、可观测与生产运行

当前计划已有 mock 端到端测试和本地模型烟测，但这不能单独证明真实运行质量。生产门槛应包含固定写作样本、人工参考答案、真实运行轨迹、成本/用量与延迟、故障路径、数据备份恢复。计划新增这些验证项，并要求阻塞如实记录，不用模拟结果替代真实证据。

### 学习与求职目标

`agent-learning` 已形成从理论到业务设计、源码调用链、最小实践、失败复盘和面试表达的学习方法。进度记录显示安全阻塞已解除，架构、安全、RAG、评测、状态与恢复已有首轮学习；判据表达、跨层归位、恢复的执行与状态两侧仍需换场景复测，可观测性收尾未完成。因此本计划以 2026-10-10 的学习记录为基线，要求每波留下负责人的复述、故障演练或设计复盘证据，不重复复制课程材料。

## 本次同步

- PRD 增加项目负责人的学习目标及 Agent 设计原则，明确其不扩大产品功能范围。
- 实施计划新增最小可验证闭环顺序、当前学习基线和每波学习产出。
- 计划命令范围补齐 PRD 已要求的 `/note`、`/idea`、`/profile`、`/reload`、`/style 提炼`。
- 生产验证门槛补充真实模型记录、安全与故障演练、写作样本评测、数据恢复演练及负责人掌握验证。
- 本次后续确定阶段/每周复盘机制：复盘规则写入 `docs/learning/2026-10-19-review-loop.md`，计划各波加入复盘与回看，ADR 0010 记录其长期流程约束。

## 未纳入本次修改

- 不新增多智能体、云服务、多租户、自动发布、向量检索等产品能力。
- 不改变已接受 ADR 的技术选型，也不把当前技术方案中的组件数量视作最终实现强制要求。
- 不修改外部 `agent-learning` 学习工作区；只引用其进度事实。
- 不将求职结果承诺写成软件验收条件；项目只需产出可追溯、可讲解的工程证据。

## 建议的阶段验收证据

1. 能用当前项目解释确定性阶段流程与模型自主决策的边界。
2. 能展示一次正常写作运行和对应执行记录。
3. 能演示至少一种权限拒绝、工具失败或中断恢复场景，并解释判据与责任层。
4. 能用固定样本说明质量评估方法、失败案例和改进依据。
5. 能讲清关键取舍、替代方案、限制和下一步，而不只介绍所用框架。
