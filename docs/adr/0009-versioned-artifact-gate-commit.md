# 版本化产物与确认原子提交

- 状态：accepted
- 日期：2026-09-28

阶段产物、用户确认和阶段推进必须绑定到同一个 `ArtifactVersion`（产出版本）并通过一次原子提交完成。确认卡记录产物内容指纹和确认内容指纹；流转前重新校验两者，任一变化都使确认失效。这样避免“数据库字段已保存但正文结构未同步”导致会话状态、文件内容和恢复检查点互相矛盾。

## 决策

1. 每个可流转阶段先生成 `temporary` 产物，并通过 `StageArtifactValidator`（阶段产物校验器）检查必需字段和必需章节。
2. 用户确认的是带 `artifactId`、`artifactHash` 和 `confirmationHash` 的决策包，不是抽象的阶段名称。
3. 批准、拒绝或要求修改都由 `WorkflowStateService`（工作流状态服务）统一提交；它在一个 SQLite 事务内完成产物状态、门禁记录、会话阶段、Trace 和稳定 checkpoint 的更新。
4. Agent 节点只生成候选和推荐，不直接写入“已确认”状态，也不直接推进阶段。
5. 确认卡默认展示 Agent 推荐及其依据、风险和备选项；用户可以直接批准推荐，也可以修改或拒绝，不要求用户先独立比较所有候选。
6. 外部编辑、回退、新版本生成、标题或确认卡内容变化，统一视为当前确认失效，必须重新确认。

## 取舍

- 不把所有阶段内容都复制进 SQLite：Markdown 大纲和主稿仍由文件作为内容权威，数据库只保存版本状态、指纹和确认关系。
- 不把 `yxj-content-workflow-v5` 的多平台、视觉和发布阶段纳入 MVP：只吸收其已验证的版本指纹、结构门禁、推荐确认和审查子阶段机制。
- 不新增一个独立的用户确认门禁：内容诊断和确定性修改属于 `review` 内部子阶段，普通模式仍保持四个内容确认点。

## 影响

- `ArtifactVersion` 需要记录产物类型、版本号、内容指纹和确认状态。
- `Gate` 需要记录确认对象指纹、确认卡指纹、推荐内容和用户决定。
- `StorePort` 需要提供原子确认提交能力；阶段节点不得绕过该入口写会话阶段。
- 阶段最低完成条件必须从自然语言规则细化为可执行结构契约。
- 研究结果需要保留研究计划、筛选标准、来源时间和保留/淘汰原因，便于解释推荐结果。
