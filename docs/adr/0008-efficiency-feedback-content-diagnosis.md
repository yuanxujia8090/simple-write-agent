# 0008：效率、反馈与内容诊断

- 状态：accepted
- 日期：2026-09-04

为满足"快速到草稿、过程可交互、内容有质量反馈"的产品预期，补四项关键决策：研究预算（限制研究深度、防止过度研究）、到稿交互数指标（固化"草稿前 2–3 次确认"）、软性内容诊断（内化 dbs-content 三维度）、会话内自由反馈（`/note`）与跨会话想法速记（`/idea`）。

## 已确认决策

1. **研究预算**：研究以轮次为单位，普通模式默认 2 轮、快速模式默认 1 轮，每轮搜索调用 3 次（2026-09-07 修订：原为 ≤ 2 次，改为 3 次；计数与结果无关，调一次算一次，不论是否有结果返回）；达到上限自动收敛到素材确认 → 论点，用户可要求“再研究一轮”。与 `maxRounds`（Agent 质量重试上限）是两套独立预算：前者控研究深度，后者控产出重试。
2. **到稿交互数指标**：从启动到首版草稿之间用户经历的确认/输入次数，目标 2–3 次以内；纳入 Trace 质量指标（与终稿验收率、平均修订轮次、拒绝反馈分类并列）。
3. **内容诊断（软性）**：普通模式 review 阶段附加文字洁癖、表达效率、认知落差三项软性诊断（参考 dbs-content，但不绑定其"先有产品"营销价值观）；作为建议呈现，不构成硬门禁。完整可插拔"内容诊断 Provider"留作后续 feature。
4. **会话内自由反馈（/note）**：任意阶段插入自由反馈，写入会话上下文与 Trace，不阻塞流程、不触发回退；与修订指令（触发回退）语义区分。
5. **想法速记（/idea）**：独立跨会话模块，MVP 提供记录（`/idea add`）、搜索/列表（`/idea`、`/idea search`）、基于想法启动新会话（`/idea use`）三能力；存全局 `ideas` 表（并入 `session.db`）；分类/待办/从审查沉淀想法等留作扩展。

## 考虑过的方案

- 内容诊断：完整 ContentDiagnosisProvider 可插拔（复杂度过高）；完全不集成（缺失内容质量维度）→ 选轻量内化三维度。
- 研究预算：不设上限（可能无限研究）；仅限每轮次数（无法控制总深度）→ 选轮次上限。
- 到稿效率：仅设计原则不统计（无法验证）→ 选固化指标 + 遥测。
- 想法模块：MVP 只做记录、查询、基于想法写作三能力；分类/待办等后续扩展。

## 影响

`session.db` 新增 `ideas` 表；`/note`、`/idea` 加入交互命令（PRD 2.2）并接入 T13；研究预算接入 T9/T10；到稿交互数接入 T6；内容诊断接入 review 阶段（PRD 3.6.3）；对应任务 T5/T6/T9/T10/T13/T15/V4 同步更新。
