# 0010：以可验证闭环推进并把学习证据纳入阶段验收

- 状态：superseded
- 日期：2026-10-19
- 已取代：2026-10-29，见 [0011：先实现、阶段留证、完成后学习](0011-implementation-first-learning-after.md)。本文件保留为历史依据；负责人学习证明不再作为开发前置条件或软件阶段放行条件。最小闭环、运行验证和记录边界继续沿用新决策。

本项目同时交付本地写作 Agent 和负责人的 Agent 工程学习证据。实现按最小可运行闭环逐步扩展；每个关键阶段既验收软件行为，也通过负责人复述、故障演练或设计复盘验证其理解，不以 AI 生成代码或说明代替掌握证明。产品范围和已接受技术决策不因学习目标而扩大。

## 复盘机制

项目与学习复盘在阶段结束时执行；每周第一次项目工作会话检查一次；明显返工、设计遗漏、验证误判或协作偏差可即时复盘。下一阶段开始时回看上次改进行动。记录必须依据证据，区分事实与假设；每次最多提炼 3 条经验，每条对应具体行动、验证方法和回看条件。助手只在当前对话中检查并提醒，不承诺后台定时推送。详细步骤、模板和学习记录边界见 `docs/learning/2026-10-19-review-loop.md`。

## 影响

- PRD 将学习目标和 Agent 设计原则与产品功能分开说明。
- 实施计划按最小闭环推进，增加真实运行、安全、恢复、评测、成本/延迟及负责人学习证据，并在阶段收尾执行复盘、阶段开始回看行动。
- `agent-learning` 是学习进度唯一事实来源，本项目只引用当前相关基线和实践证据；无真实学习证据时不代记掌握结论。
- 两个工作区双向读取当前阶段、学习状态和相关复盘，并通过路径互相引用；项目实践复盘与学习掌握记录分开维护。
- 生产可用声明必须由真实运行与恢复证据支持；mock 和静态检查只能证明其覆盖范围内的性质。
