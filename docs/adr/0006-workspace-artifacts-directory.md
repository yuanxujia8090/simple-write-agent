# 0006：工作目录与全局状态目录分离

- 状态：accepted
- 日期：2026-09-04

PRD 未定义"工作目录"概念，导致 `articles/`、`--file`、`--output-dir` 等路径解析基准悬空。决策：引入工作目录（Workspace）与全局状态目录分离的两层模型。工作目录默认等于启动 `writing-agent` 的当前目录，可用 `--cwd <path>` 覆盖，是文件产物（大纲、主稿 Markdown + HTML）的落盘位置；全局状态目录 `~/.writing-agent/` 统一存放配置（`config.json`）、作者档案（`profile.db`）、会话状态库（`session.db`）和素材快照（`materials/<sessionId>/`），与工作目录解耦。会话记录创建时的 `workspace` 绝对路径；欢迎页按 `workspace` 匹配未完成会话并提示恢复，不自动进入。

工作目录通过轻量标记 `.writing-agent/workspace.json`（含 `workspaceId`）识别：首次在某目录创建会话时写入；启动时从当前目录向上逐级查找最近标记以认领工作目录（在 `articles/` 或任意子目录启动也能认领回原工作目录），`--cwd` 显式指定时跳过查找；目录改名/移动后靠 `workspaceId` 仍可关联全局库会话。标记只存元数据，不存会话状态。

大纲（`outlines/<slug>.outline.md`）与草稿主稿（`articles/<slug>.md`）落盘为文件，**文件是内容权威，DB 只存版本状态、确认记录与 mtime/hash 指纹**。Agent 在读取或重写落盘产物前执行外部编辑检测：检测到文件被外部修改则停下询问用户（确认采用 / 重新生成 / 忽略改动），不静默采用、不静默覆盖；检测时机为进入 outline 确认前、进入 drafting 前、进入 review 前、导出前，MVP 不做后台实时监控。

## 考虑过的方案

- 状态库放工作目录内 `.writing-agent/`：目录即状态、拷走即带走会话，但 `/list` 需要聚合多个库，且素材/库与产物分离多处；
- 素材引用原路径不复制：实现最简，但工作目录搬移或原文件改名后会话内素材失效；
- 只按 `workspace == 当前目录` 精确匹配、不向上回溯：在产物子目录（如 `articles/`）启动时无法认领回原工作目录，违背"产物目录启动读取创作状态"的目标；
- 落盘产物全部进 SQLite、不落盘：用户无法直接外部编辑大纲/草稿，违背"中间产物用户会直接修改"的场景。

## 影响

`--cwd` 新增为启动参数；全局单库使 `/list` 天然全局；确认纳入的素材复制为快照；导出路径相对工作目录解析；启动时需执行工作目录向上回溯解析；大纲与主稿落盘并纳入外部编辑检测（mtime/hash 指纹入库、检测到改动中断询问）；SQLite 存储任务（T5）与配置任务（T2）需同步工作目录解析和全局目录初始化。
