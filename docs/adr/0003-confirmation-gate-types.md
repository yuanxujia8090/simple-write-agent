# 0003：确认门禁分为采纳与内容两类

- 状态：accepted
- 日期：2026-09-04

PRD 同时要求"用户整批确认素材"和"普通模式 4 个确认点"，但两者若都作为同一类门禁，会让 TUI 出现第 5 张确认卡，输入采纳与输出批准的语义混在一起。决策：把确认门禁分为采纳门禁（AdoptionGate，决定什么信息进入素材池/上下文）与内容门禁（ApprovalGate，决定什么内容进入终稿）。素材整批确认属采纳门禁；论点/大纲/事实报告/终稿属内容门禁；用户显式 `/read` 直接进入素材池，不设卡。快速模式自动采纳素材并标记为"待验证"。

## 考虑过的方案

- 把素材确认并入内容门禁之一：会让"确认门禁"同时管输入与输出，输入采纳逻辑与 Agent 自主采集内容的噪音控制耦合。
- 不设采纳门禁，Agent 读取的内容直接进池：失去对 Agent 自主采集内容的用户控制，污染素材池。

## 影响

TUI 确认卡区分采纳/内容两类；SQLite 需要门禁记录字段；快速模式素材的"待验证"状态进入 Material 数据结构。
