# 0004：事实核查规则层只验证可追溯性

- 状态：accepted
- 日期：2026-09-04

质量门禁成立的关键在"争议检测"，而规则层无法做语义级真伪验证，试图做真伪验证是过度工程。决策：规则层只验证可追溯性，判定三类可复现的争议信号——缺来源（外部硬事实无 source 字段）、来源不可验证（URL/路径无法读取或验证存在）、硬事实占比异常（单篇超过 40%）；真伪判断交给用户。快速模式的事实降级改写遵守"只降级、不新增"，禁止在改写中产生新的内容断言，每条降级带原因代码（无来源 / 不可验证 / 来源冲突）。

## 考虑过的方案

- 规则层做来源内容与声明的语义比对：超出 MVP 范围，需要检索与语义模型。
- 依赖模型自评"这句事实可信吗"：模型自评防不住"编一个事实 + 编一个来源"的失效模式。

## 影响

Evidence 需要来源验证状态与原因代码字段；`checkFacts` 输出结构化争议信号；快速模式改写受"只降级不新增"约束；来源逐句语义比对作为后续增强，不进入 MVP。
