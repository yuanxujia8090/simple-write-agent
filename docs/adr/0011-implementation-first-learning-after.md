# 0011：先实现、阶段留证、完成后学习

- 状态：accepted
- 日期：2026-10-29
- 取代：[0010：以可验证闭环推进并把学习证据纳入阶段验收](0010-learning-first-incremental-validation.md)
- 决策依据：2026-10-29 用户明确要求解除“先学习后开发”的限制，先实现，各阶段记录技术方案与技术决策，完成后再回看学习。

## 决策

1. 项目按最小可运行闭环逐步实现。负责人课前讲解、复述、答题、课程完成度和学习复测均不再作为开发前置条件、阶段放行条件或软件交付条件。
2. 每个实施阶段开始时，在 `docs/design/` 记录本阶段目标、范围、输入输出、责任边界、失败处理和验证方案；阶段内发生关键技术取舍时，记录独立 ADR（Architecture Decision Record，架构决策记录）。在已授权范围内有推荐方案时直接采用并说明理由；涉及不可逆操作、费用、对外发布或需求范围变化时先请用户确认。
3. 每次代码需求在 `docs/changes/` 记录实际修改、验证命令、结果、剩余风险及对应方案/决策。阶段收尾及时补齐证据与实现偏差；不为等待学习复盘而阻塞下一阶段。
4. 软件放行仍取决于功能、测试、运行、安全、恢复和数据保护等工程证据。解除学习限制不降低软件验证要求，也不把模拟测试等同于真实模型运行。
5. 软件实现后，负责人以阶段方案、决策、代码和运行记录为材料回看学习。阶段中可以收集待学问题，但不强制插入讲课或答题。
6. 学习进度仍只在 `/Users/yuanxj/Documents/knowledge-space/learn-agent/agent-learning/` 记录；项目只保存实践材料并引用该路径。没有本人真实学习证据时，不更新掌握状态或分数。

## 取舍与影响

- 保留最小闭环推进、失败验证、阶段记录和历史决策；取消学习证明与开发放行的绑定。
- 不一次性重写全部设计；实施到哪个阶段，就细化哪个阶段的方案，并及时把已验证结论同步到需求、总设计和计划。
- 本决策调整开发与学习顺序，不改变写作产品的功能范围，不授权自动发布、付费调用或不可逆操作。
- `agents.md`、需求 §1.5、实施计划和项目复盘规则同步采用本决策；历史审查与研究材料保留，阅读时以当前文档入口区分有效规则与历史背景。
