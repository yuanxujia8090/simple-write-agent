## 2026-10-29：启动阶段实施取舍

- **工具链最小化**：已按推荐选了 Node 22 ESM + tsx + Vitest + TypeScript 7，参数解析用标准库 `parseArgs`，不引入 commander/yargs 或打包器。原因：本阶段只验证启动链，少一层构建和依赖就少一处和真实运行不一致的地方；后续如果参数变复杂再评估。
- **配置默认值指向本地**：默认 `provider=openai-compatible`、`baseURL=http://localhost:11434/v1`、`modelId` 留空。原因：产品是本地优先，留空比填一个假模型名更诚实，`firstRun` 会提示用户填写；代价是 CLI 概览显示空模型名，属预期。
- **`markerPath` 只表示“实际读到的标记”**：`--cwd` 指向没有标记的目录时返回 `null`，不是“将来要写入的路径”。原因：一个字段只表达一个事实，避免调用方误以为标记已存在；写入路径可由 `MARKER_DIR`/`MARKER_FILE` 重算。
- **确认幂等键**：`(artifactId, artifactHash, confirmationHash, decision)` 四元组作为唯一键。原因：T0 E2 实测同一决策第二次提交能被识别为 `duplicate_confirmation`，且不依赖自增序号；`artifactId` 保证不同产物的相同文字不会互相吞掉确认。
- **文件与数据库边界的对账策略**：主稿先写临时名再 `rename` 到正式路径；崩溃后对账把无 DB 记录的正式文件判为“未登记版本”，要求人工 adopt（登记为 temporary）或 discard（移到 `.discarded`，不删除）。原因：T0 E4 实测这两种选择都能收敛，且满足“不静默采用、不静默覆盖”；直接删除文件会让用户的编辑成果不可恢复。
- **故障注入代替真实杀进程**：E3/E4 用事务内抛错模拟进程在提交前退出。原因：可重复、可断言；限制是没覆盖操作系统层面的断电/强杀，真实崩溃演练放在 T15。
- **锁暂不接入启动流程**：锁实现与测试已完成，但 `writing-agent` 启动时不获取锁。原因：本阶段要求“任何创建用户数据目录的行为只在用户明确启动会话后发生”，会话库尚不存在，提前加锁只会制造空锁文件。
