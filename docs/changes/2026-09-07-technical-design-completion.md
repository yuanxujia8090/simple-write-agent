- 日期：2026-09-07

## 变更目的

解决评审讨论中确认的三个文档缺口，使技术方案从"图的骨架"补全到"模型怎么干活"：

1. 模块职责边界只有"职责/不做什么"两维，缺协作契约（接口签名、状态所有权）；
2. 模型节点内部执行模型（agent loop、工具循环、预算、失败处理）未设计；
3. 记忆体系（工作记忆 / checkpoint / 作者档案三层）与上下文组装策略未设计；
4. LangGraph 与 Vercel AI SDK 的协作机制只有 ADR 结论、无落地细节。

## 后续决策落地（同日，架构师审查 7 项决议）

用户对审查问题逐项拍板后，追加落地：

1. **搜索预算改为每轮 3 次**（原 ≤ 2 次）：计数与结果无关，调一次算一次；搜索预算为硬约束，优先于 maxSteps，工具执行前检查。同步修改：设计文档 §15.3、§12.1 性能表、ADR 0008、计划 §5.5 与 T9、PRD 3.6.2 与验收 16。
2. **research 节点降级路径**：无工具可用后暂停并提示用户，用户决策——跳过本轮研究（标待验证）或放弃研究阶段（直接进素材确认）；其他节点保持“去掉 tools 重跑”。设计文档 §15.4。
3. **新增 §15.6 节点执行配置表**（节点 × 模型模式 × 模型可自主调用工具 × maxSteps），并明确写盘类工具（writeDraft/exportMarkdown）由节点代码经 FilePort 执行、不暴露给模型自主调用。
4. **文件与消息一致性规则（§16.4）**：文件是内容权威；外部编辑确认后对应消息段标记失效；回退时下游消息一并失效；结构化产物确认后转写为确认记录消息进 messages；由消息失效管理器实现。
5. **超限报错改进**：提示时列出未被证据引用的素材清单。
