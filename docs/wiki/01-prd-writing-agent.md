## 1. 产品概述

### 1.1 产品定位

写作 Agent 是一个本地运行的 TypeScript TUI/CLI（终端交互程序）。用户输入话题、文字素材，或恢复中断的写作会话，Agent 协助完成公众号长文的研究、论点收敛、大纲、草稿、审查和导出。

产品的核心不是一次性生成文本，而是保存写作过程中的状态、用户确认和历史成果，使流程能够中断恢复、拒绝重做和追踪回放。

### 1.2 MVP 目标

用户能够：

1. 通过话题、`.txt`/`.md` 文字素材或已有会话开始写作；
2. 在信息不足时通过 Agent 访谈补齐创作简报；
3. 对论点、大纲、事实核查报告和终稿进行人工确认；
4. 在中断、误操作或拒绝后恢复流程且不丢失已有成果；
5. 得到同一份 Markdown 主稿和由它确定性生成的公众号内联样式 HTML。

### 1.3 目标用户

MVP 面向单个独立内容创作者，当前优先满足项目负责人自己的公众号长文创作流程。

### 1.4 不在 MVP 范围内

- 热点筛选和选题推荐；
- 小红书及其他平台的独立成文流程；
- 自动发布、账号系统、云端多租户；
- 图片、封面、视频等视觉素材；
- PDF 等输入格式；输入短期只支持 `.txt` 和 `.md`；
- 向量数据库和 embedding 检索；
- 主题可视化编辑器及主题导入/导出命令；
- 复杂搜索优化；搜索能力先用一个第三方实现，后续再单独优化；
- 直接复制 Pi coding agent 或 Hermes agent 的代码或实现。

## 2. 用户入口与交互

### 2.1 启动命令

`writing-agent` 是 Agent 的名称，也是可执行命令。用户输入：

```bash
writing-agent
```

命令执行后直接进入 TUI/CLI 交互模式，不要求再输入 `run`。

支持用于快捷启动的参数：

```bash
writing-agent --topic "主题"
writing-agent --file ./notes.md
writing-agent --theme ./my-theme.json
writing-agent --cwd <路径>
writing-agent --fast
```

用户可以在任意目录启动 `writing-agent`。未指定 `--cwd` 时，当前启动目录即为工作目录（Workspace，见 4.7）；`--cwd <路径>` 可显式指定其他目录作为工作目录。

`writing-agent` 不带参数启动后进入欢迎页（idle 主界面），提供新建会话、恢复会话、退出三个入口，不强制直接进入访谈。欢迎页按解析出的工作目录（含向上回溯，见 4.7）检测是否有未完成会话（工作目录与该会话的 `workspace` 匹配），有则提示"N 个未完成会话，`/resume` 恢复"，不自动进入。

### 2.2 交互命令

交互模式至少支持：

| 命令 | 作用 |
|---|---|
| `/new` | 创建写作会话；可追加话题或素材路径 |
| `/list` | 查看未完成会话 |
| `/list --all` | 查看全部会话 |
| `/resume` | 选择并恢复会话 |
| `/search <关键词>` | 手动搜索资料 |
| `/read <路径>` | 手动读取 `.txt`/`.md` |
| `/export` | 导出当前终稿，支持 `--copy` 复制 HTML 到剪贴板 |
| `/note <内容>` | 向当前会话插入一条自由反馈，供后续阶段参考（见 2.4） |
| `/idea` | 想法速记：`/idea add <内容>` 记录、`/idea search <关键词>` 搜索、`/idea use <id>` 基于想法启动新会话（见 2.4） |
| `/profile` | 查看和编辑作者档案（语言风格、背景、偏好） |
| `/help` | 查看帮助 |
| `/exit` | 保存检查点并退出 |

用户可以通过交互命令或快捷参数提供话题、素材和主题；没有话题、素材或可恢复会话时，系统进入访谈以形成创作简报，不自行生成热点选题。

### 2.3 会话列表

默认 `/list` 只展示未完成会话；`/list --all` 展示全部会话。每项至少展示：

- 会话名称；
- 会话状态；
- 更新时间；
- 当前阶段；
- 最近一次用户可感知事件。

Agent 为新会话生成默认名称（`主题前 8 字 + 日期`），用户可以修改。`/list` 每项的"最近一次用户可感知事件"取最近一条 Trace 的类型 + 简述。MVP 不提供会话删除。

### 2.4 自由反馈与想法速记

**会话内自由反馈（/note）**：用户可在任意阶段输入 `/note <内容>`，插入一条自由反馈到当前会话上下文并记入 Trace，供后续阶段参考。自由反馈不阻塞当前流程，不改变阶段状态，仅作为后续创作的输入约束之一（与修订指令不同，`/note` 不触发回退）。

**想法速记（/idea）**：独立的跨会话灵感记录模块，不依赖当前会话，任意时刻可调用：

- `/idea add <内容>`：记录一条想法，存入全局库 `ideas` 表；
- `/idea search <关键词>` / `/idea`：搜索 / 列出想法；
- `/idea use <id>`：以该想法作为话题/创作简报起点启动新会话（进入 `intake`）。

MVP 只提供记录、查询、基于想法写作三个能力；分类、待办状态、从审查反馈沉淀想法等作为后续扩展。

## 3. 核心用户流程

### 3.1 阶段流转

```text
idle → intake → research → thesis → outline → drafting → review → exported
```

`interview` 不是独立固定阶段，而是 `intake` 信息不足时触发的访谈子流程。

所有新会话先经过 `intake` 检查：信息足够则进入 `research`；信息不足则通过固定问题访谈用户，生成创作简报并等待用户确认。

### 3.2 输入与创作简报

支持以下输入组合：

- 只有话题；
- 只有 `.txt`/`.md` 文字素材；
- 话题与文字素材同时提供；
- 从已有中断会话继续。

创作简报（Creative Brief，明确文章写给谁、为什么写和写什么）最低包含：

- 主题；
- 目标读者；
- 写作目的。

用户可以直接编辑简报，也可以输入自然语言反馈让 Agent 修改。简报每次变化后必须重新确认。

访谈采用”固定问题 + 用户确认”的方式，用户可以继续补充信息。缺信息时先搜索，搜索不到再提问用户。

MVP 固定问题集（映射 CreativeBrief 字段）：

1. 主题是什么？（→ 主题）
2. 这篇文章写给谁？（→ 目标读者）
3. 希望读者读完后做什么 / 为什么写？（→ 写作目的）
4. 有没有必须用到的素材或限制？（可选 → 约束）
5. 语气或视角有没有偏好？（可选，缺省时从 WriterProfile 补齐）

答完 1–3 即可进入简报确认；4–5 可跳过。用户可在任意问题点直接要求”就用这个开始”。

### 3.3 研究与素材

研究阶段可以使用：

- 用户提供或用户确认的本地 `.txt`/`.md` 素材；
- 可插拔的 WebSearch（网页搜索）能力；
- 用户手动输入的 URL。

读取结果先记录到 Trace（执行记录），不会自动进入当前会话的素材池。按发起方区分归属：

- Agent 工具主动读取（`readMaterials`、`readWeb`）→ 先入 Trace，用户整批确认后进入 Material（素材）集合；
- 用户显式 `/read <路径>` → 直接进入 Material，不设确认卡（显式命令即为采纳动作）；
- 用户 `/search <关键词>` 的结果 → 先入 Trace，整批确认后进入 Material（搜索结果噪音较多，值得过滤）。

素材整批确认属于采纳门禁（AdoptionGate，决定哪些信息进入素材池/上下文的确认门禁），与内容门禁（ApprovalGate，决定哪些内容进入终稿的确认门禁）分开建模；普通模式保留此确认点，快速模式自动采纳并将未验证内容标记为"待验证"，不设卡；快速模式待验证素材对应的外部硬事实自动进入终稿确认时的降级改写清单（原因代码 = 未验证素材）。

素材确认纳入后，复制为会话快照存入全局素材目录 `~/.writing-agent/materials/<sessionId>/`（见 4.7），不引用原路径；原文件后续改动不自动同步到快照。

素材输入边界：`--file` 可重复指定；单个素材文件 ≤ 1MB；编码为 UTF-8（容忍 BOM）；超限或编码错误给出可读提示，不崩溃。

只读工具允许 Agent 在任意阶段调用，也允许用户通过交互命令或独立 CLI 入口调用；写入工具仍受阶段权限限制。

搜索失败分为两类分别处理：基础设施失败（超时、凭据错误、非 2xx 响应）连续 2 次后暂停并询问用户是否跳过，跳过结果标记为待验证；质量失败（模型输出未满足阶段最低完成条件）走重试或降级，不进搜索的暂停逻辑。

研究预算（防止过度研究）：研究以**轮次**为单位（每轮 = Agent 提出搜索/读取计划 → 执行 → 结果入 Trace → 汇总），普通模式默认 **2 轮**、快速模式默认 **1 轮**，每轮搜索调用 ≤ 2 次。达到上限后自动收敛到素材确认 → 论点；用户仍可主动要求"再研究一轮"。研究预算与 Agent 质量重试上限（`maxRounds`）是两套预算：前者控制研究深度，后者控制产出不达标时的重试次数。

### 3.4 论点与大纲

`thesis` 阶段生成至少 3 个、最多 5 个论点候选。每个候选包含：

- 核心主张；
- 简要论证思路。

用户确认一个论点后，进入 `outline`。大纲至少包含：

- 标题；
- 章节列表；
- 每章写作目标。

确认后的大纲写入 `<工作目录>/outlines/<slug>.outline.md`（见 4.7），用户可直接用外部编辑器修改。大纲被外部编辑后，进入 drafting 前由外部编辑检测触发确认：提示用户选择"确认采用 / 重新生成 / 忽略改动"；确认采用后以新大纲继续，重新生成则回到 `outline`（保留修改文本作参考），忽略则继续用已确认版本。

### 3.5 草稿与外部编辑

`drafting` 阶段生成 Markdown 草稿，目标长度为 2000–5000 字。该范围是 MVP 的生成目标，不作为绝对阻止导出的硬门禁。草稿主稿写盘于 `<工作目录>/articles/<slug>.md`（见 4.7）。

用户可以用外部编辑器修改 Markdown 主稿。外部编辑检测（见 4.7）在回到 review / 准备导出前触发，提示用户是否重新进入 `review` 和 `export` 流程；用户确认后，主稿重新进入事实核查、终稿确认和导出，不静默采用外部改动。

### 3.6 审查与事实规则

#### 3.6.1 作者档案（WriterProfile）

写作 Agent 维护一个跨会话、全局的作者档案 `WriterProfile`，记录用户的语言风格、身份背景、内容偏好和写作禁忌，并在后续创作时影响作品。档案保存在应用内部存储（SQLite）中，方便查看、编辑和溯源，不放在全局文件目录。

MVP 阶段档案只通过手动方式维护：

- 用户通过 `/profile` 命令查看和编辑档案；
- 档案分类：语言风格、写作禁忌、身份背景、内容偏好；
- 每条档案记录包含来源（手动录入或某次审查反馈）、状态（候选/生效/停用）和更新时间；
- 新会话进入 `intake` 时，将生效中的档案条目注入创作简报上下文，作为写作风格的约束。

后续可评估自动识别能力（类似 Hermes agent 的 memory 机制），当前不调研、不实现，仅作为后续 feature 标记。

#### 3.6.2 事实规则

LLM（Large Language Model，大语言模型）先将内容分类为：

- 外部硬事实；
- 个人经验；
- 观点；
- 推测。

规则层校验分类结果，争议项交给用户处理。

主稿被外部编辑并确认重新审查后（见 3.5），事实核查针对新主稿重新执行：普通模式重新生成核查报告并等待用户确认，快速模式重新执行降级改写并更新降级清单。

规则如下：

1. 外部硬事实必须有来源；
2. 个人经验可以没有外部来源，但不能由 Agent 凭空推断为用户经历；
3. 观点和推测可以进入终稿，但必须保持相应表达，不能伪装成外部事实；
4. 访谈回答先进入 Material，涉及外部事实时仍需 Evidence（证据）核查；
5. 普通模式下，无来源外部硬事实不得进入终稿；
6. 快速模式仍执行事实核查；无法验证的硬事实自动改写为个人经验、观点或推测，不阻塞流程；改写遵守”只降级、不新增”——只能降级或删除，禁止在改写中产生新的内容断言；每条降级带原因代码（无来源 / 不可验证 / 来源冲突）；
7. 快速模式在终稿确认时展示”事实降级改写清单”，清单每项附原因代码，供用户判断是否接受该降级。

规则层不负责验证事实真伪，只验证可追溯性，判定以下可复现的争议信号：

a. 缺来源：外部硬事实无 source 字段 → 打回，强制补来源或改写；
b. 来源不可验证：source 是 URL 或文件路径，但无法读取或验证存在 → 标记”待验证”，列入争议清单交用户；
c. 硬事实占比异常：单篇外部硬事实占比超过 40% → 提醒用户抽查。

真伪判断交给用户；来源内容与声明的逐句语义比对作为后续增强，不在 MVP。

#### 3.6.3 内容诊断（软性）

普通模式 review 阶段除事实核查外，附加一项**软性内容诊断**（不构成硬门禁，不作为通过条件）：参考 dbs-content 的诊断维度，检查草稿的

- 文字洁癖：是否存在明显 AI 味（Emoji 堆叠、晦涩词汇、空洞排比）；
- 表达效率：能否一句话说清核心观点；
- 认知落差：表达相比常见内容是否有明显差异。

诊断结果以建议形式呈现在事实核查报告中，由用户决定是否采纳；不拦截导出。MVP 只做这三项轻量内化，不做完整五维诊断，也不绑定 dbs-content 的营销导向价值观；完整可插拔"内容诊断 Provider"作为后续 feature。

普通模式在事实核查报告后等待用户整体确认；快速模式跳过该人工确认，但不能跳过核查执行。

### 3.7 确认门禁

本节确认点均指内容门禁（ApprovalGate）；素材采纳门禁（AdoptionGate）见 3.3。普通模式包含 4 个内容确认点：

1. 论点确认；
2. 大纲确认；
3. 事实核查报告确认；
4. 终稿确认。

快速模式通过 `--fast` 启动，保留：

1. 论点确认；
2. 终稿确认。

确认界面使用 Ink（React 终端渲染框架）渲染确认卡和键盘操作。

拒绝采用"最小回退"：回退到产生被拒绝产物的阶段（父阶段），不提供自由选择回退深度：

| 被拒产物 | 回退目标 | 保留的已确认上下文 |
|---|---|---|
| 论点候选 | `thesis` | 创作简报、素材 |
| 大纲 | `outline` | 已确认论点、素材 |
| 事实核查报告 | `research` | 已确认论点、大纲、素材 |
| 终稿 | `drafting` | 已确认论点、大纲、素材 |

拒绝时保留原成果（`draft`/`rejected`），保存用户原始反馈和结构化修订指令，并把修订指令作为下一轮该阶段的输入约束。

## 4. 数据与生命周期规则

### 4.1 核心对象

```text
WritingSession（写作会话）
├── Topic（话题）
├── CreativeBrief（创作简报）
├── Material（素材）
├── Evidence（证据）
├── ThesisCandidate（论点候选）
├── Outline（大纲）
├── ArtifactVersion（产出版本）
├── GlobalTheme（全局主题）
├── WriterProfile（作者档案，全局、跨会话）
├── ConfirmationGate（确认门禁）
├── Checkpoint（检查点）
├── Trace（执行记录）
├── Note（会话内自由反馈）
└── Idea（想法速记，全局、跨会话）
```

`WriterProfile` 是全局唯一的作者档案，与 `GlobalTheme` 平级：主题管样式，档案管内容风格。档案不进入单篇素材池（Material），也不替代单篇创作简报（CreativeBrief）。`Idea` 是全局想法速记，独立于会话（见 2.4）。

### 4.2 素材与证据

`Material` 保存 Agent 可参考的原始文字内容；`Evidence` 保存支撑某个具体事实声明的来源。读取过的内容不自动成为证据，事实声明也不等同于原始素材。

### 4.3 产出版本

所有阶段产出都支持以下状态：

- `draft`：当前采用的成果；
- `rejected`：用户拒绝但保留的历史成果；
- `temporary`：当前执行中的临时成果。

用户拒绝不等于删除。重新执行同一阶段时，只保留最近一个 `temporary`，新的临时成果可以替换它；`draft` 和 `rejected` 保留。临时成果只用于恢复和审计，不出现在普通会话列表中。

### 4.4 检查点与恢复

`Checkpoint` 保存可恢复的流程状态；`ArtifactVersion` 保存阶段产出，两者分开建模并通过会话 ID、产出 ID 关联。

Checkpoint 以**阶段为原子单位**：每个阶段完成时写入一个稳定 checkpoint。中断后从最近稳定 checkpoint 恢复；如果中断发生在阶段执行中，则重做整个阶段，不把半成品当作完成成果。

### 4.5 主题

主题配置参考 `archive/my-theme.json`，是一套用于公众号 HTML 的样式变量，采用内联样式。

MVP：

- 读取固定主题路径或 `--theme <path>` 指定的 JSON；
- 缺失字段使用系统默认主题补齐；系统默认主题为内置默认色值，字段结构与 `archive/my-theme.json` 一致；
- 校验字段类型和取值范围；版本字段 MVP 只接受 `version: 1`，遇到其他值报错并保留旧主题，不做版本迁移路径；
- 非法配置保留旧主题并提示错误；
- 保存用户提供的原始 JSON，运行时使用补全后的主题对象；
- 不提供主题可视化编辑器和主题导入/导出命令；
- 全局主题只影响重新导出，已经导出的文件不变。

### 4.6 导出

Markdown 是主稿。HTML 按 Markdown 节点类型确定性渲染，使用主题 JSON 生成内联样式，不让模型分别生成 HTML。

HTML 支持的标准 Markdown 节点集（mdast 子集）：标题、段落、引用、代码、列表、表格、图片、强调、链接、分隔线。不属于该子集的内容保留原文并给出警告，不静默丢弃。

默认输出（相对工作目录，见 4.7）：

```text
<工作目录>/articles/<slug>.md
<工作目录>/articles/<slug>.html
```

支持 `--output-dir` 和用户指定 slug；未指定时从标题生成（保留中文，清理 `/ \ : * ? " < > |`，空格转 `-`），文件冲突时使用 `slug-2`、`slug-3`，不覆盖既有文件。`--output-dir` 指定绝对路径时使用该路径；否则相对工作目录解析。

默认不输出来源信息，来源保存在会话和 Evidence 中。HTML 导出失败时标记为部分成功，保留已生成的 Markdown，并允许单独重试 HTML。

`/export --copy` 可将 HTML 复制到剪贴板，供公众号编辑器直接粘贴；复制不改变导出文件行为。

### 4.7 工作目录与产物目录

**工作目录（Workspace）**：会话与文件产物的默认根。默认等于启动 `writing-agent` 时的当前目录，可用 `--cwd <路径>` 显式覆盖（见 2.1）。每个会话记录创建时的 `workspace` 绝对路径。

工作目录解析规则：

1. `--cwd <路径>` 显式指定 → 以该路径为工作目录；
2. 否则从当前目录向上逐级查找最近的 `.writing-agent/` 标记，找到则以标记所在目录为工作目录（在 `articles/` 或任意子目录启动都能认领回原工作目录）；
3. 未找到标记 → 当前目录即为工作目录；
4. 首次在某目录创建会话时，写入 `.writing-agent/workspace.json`（`workspaceId`、版本、创建时间），作为该目录的身份锚点；目录改名/移动后仍可通过 `workspaceId` 关联全局库会话。

工作目录结构（Agent 只管理下列前三项，其余为用户自己的文件，不干预）：

```text
<工作目录>/
├── .writing-agent/             # 工作目录标识（轻量元数据，不存会话状态）
│   └── workspace.json          # { workspaceId, version, createdAt }
├── outlines/                   # 大纲落盘：<slug>.outline.md（可被用户外部编辑）
├── articles/                   # 草稿主稿 + 导出：<slug>.md + <slug>.html
└── inputs/                     # （可选软约定）素材来源目录，仅供用户整理，无功能依赖
```

全局状态目录 `~/.writing-agent/` 存放所有会话数据，与工作目录解耦：

```text
~/.writing-agent/
├── config.json                  # 配置
├── profile.db                   # 作者档案 WriterProfile（跨会话全局）
├── session.db                   # 会话/checkpoint/Trace/素材/证据/版本/简报/修订指令/门禁
└── materials/<sessionId>/       # 素材快照（确认纳入后复制，见 3.3）
    ├── notes.md
    └── interview.txt
```

阶段产物归属规则：

- **结构化对象进 SQLite**：创作简报、论点候选、证据、事实核查报告、产出版本、修订指令、门禁记录均存入 `session.db`，不单独落盘；
- **大纲落盘**：确认后的大纲写入 `<工作目录>/outlines/<slug>.outline.md`，用户可直接外部编辑；DB 只存"当前采用版本、确认状态"，内容以文件为准；
- **草稿主稿与 HTML 落盘**：Markdown 主稿 + 确定性渲染的 HTML 位于 `<工作目录>/articles/`，主稿在 drafting 阶段写盘；
- **素材复制为快照**：确认纳入的素材复制到 `~/.writing-agent/materials/<sessionId>/`，工作目录可搬移而不丢素材。

外部编辑检测（大纲与草稿均适用）：

- Agent 在**读取某个落盘产物、或准备重写它之前**，对比文件 mtime/hash 与 DB 记录，判断是否被外部编辑过；
- 检测到外部编辑 → **停下询问用户，绝不静默采用，也绝不静默覆盖**：
  - 大纲被改 → 提示确认采用 / 重新生成 / 忽略改动（见 3.4）；
  - 草稿被改 → 提示是否重新进入 review 和 export（见 3.5）；
- 检测时机：进入 outline 确认前、进入 drafting 前、进入 review 前、导出前；MVP 不做后台实时监控。

**启动检测**：欢迎页按解析出的工作目录（含向上回溯结果）匹配全局库中 `workspace` 对应的未完成会话并提示恢复，不自动进入。`/list` 面向全局单库，天然列出全部会话；恢复的会话文件产物仍在原工作目录。

## 5. 非功能需求

### 5.1 本地优先

- Node.js + TypeScript 单进程运行；MVP 限制单进程单活动会话，检测到 `session.db` 被其他进程占用时提示"另一实例正在运行"并退出；
- 模型优先使用本地 OpenAI-compatible（OpenAI 兼容）接口；无 `config.json` 时首次启动引导填写 provider/baseURL/model，不静默使用假配置；
- 全局数据统一位于 `~/.writing-agent/`（config.json、profile.db、session.db、materials/，见 4.7）；配置支持环境变量和 `~/.writing-agent/config.json`；
- 搜索凭据支持环境变量和 `~/.writing-agent/config.json`；MVP 提供 `SearchProvider` 接口并接入 Tavily（mock 可验收，配置凭据后可用真实搜索）；
- 本地素材不主动上传，外部模型和搜索仅在用户配置后使用；素材确认纳入后仅复制到本地素材目录。

### 5.2 可恢复与可追踪

- 状态变更写入 SQLite；
- 支持会话列表、选择恢复和中断节点重做；
- 记录模型决策、工具调用、工具结果、状态变化、确认请求和错误；
- Trace 支持回放。

### 5.3 可验证

- 阶段必须满足最低完成条件；Agent 质量判断 = 结构门槛（最低完成条件）+ 规则层（事实/证据），内容质量由人工确认门禁把关，不引入模型内容自评；`maxRounds` 默认 2，仅兜底流程错误（结构不达标重试）；
- 写入类工具受阶段权限限制；
- 事实分类由模型提出、规则校验、用户处理争议；
- Markdown 与 HTML 内容必须来自同一份主稿；
- 模型、文件、配置错误均给出可读提示和可恢复路径（搜索失败已按基础设施/质量分级）；
- 关键成功和失败路径必须有自动化测试。

### 5.4 质量遥测与可取消

- 从 Trace 自动统计 4 个流程代理指标，用于评估 Agent 对作者的有效性：
  1. 终稿验收率：终稿确认次数 / 进入终稿确认的总次数；
  2. 平均修订轮次：每篇从首稿到终稿经过的 drafting 次数；
  3. 拒绝反馈分类：用户拒绝时的反馈按预定义类型归集（语气、事实、结构、长度等）；
  4. 到稿交互数：从启动到首版草稿之间用户经历的确认/输入次数（草稿前阶段应保持 2–3 次以内）。
- 指标只用于项目评估与后续 WriterProfile 自动记忆（见第 8 节）的输入，不阻塞流程。
- 耗时步骤展示进度提示（当前阶段 + 已耗时）；`Ctrl+C` 在任何节点执行 = 保存 checkpoint 并回到主界面，不强制终止。

## 6. MVP 验收标准

1. 执行 `writing-agent` 后直接进入交互模式，支持 `/new`、`/list`、`/resume`、`/search`、`/read`、`/export`、`/note`、`/idea`、`/profile`、`/help`、`/exit`。
2. 话题、`.txt`/`.md` 素材和中断会话都能进入统一 `intake` 流程。
3. 信息不足时能完成固定问题访谈并生成用户确认的创作简报。
4. 普通模式完成论点、大纲、事实报告、终稿 4 个内容确认点（另含素材采纳门禁）；`--fast` 完成论点和终稿 2 个内容确认点，素材自动采纳并标记待验证。
5. `thesis` 产生 3–5 个带论证思路的论点候选；`outline` 产生可执行大纲。
6. 生成目标长度 2000–5000 字的 Markdown 主稿，并允许外部编辑后重新审查。
7. 快速模式仍执行事实核查，并在终稿确认时展示事实降级改写清单。
8. 同一 Markdown 主稿能确定性生成公众号内联样式 HTML；导出失败可单独重试 HTML。
9. 中断、拒绝和重做不丢失已产生的 `draft`、`rejected` 成果。
10. 支持通过 `/profile` 查看和编辑作者档案；生效中的档案条目在新会话创作简报中生效。
11. `npm run typecheck`、`npm test` 和关键流程测试通过。
12. Trace 可统计终稿验收率、平均修订轮次、拒绝反馈分类、到稿交互数四项指标。
13. 在任意目录启动时默认以当前目录为工作目录，`--cwd` 可覆盖；在工作目录内启动能检测到该目录的未完成会话并提示恢复。
14. 大纲落盘于 `outlines/<slug>.outline.md`、草稿主稿落盘于 `articles/<slug>.md`；大纲/主稿被外部编辑后能检测并提示，确认采用后衔接对应流程（大纲重进 outline、主稿重进 review/export）。
15. `/note` 能在任意阶段插入自由反馈并进入会话上下文与 Trace；`/idea` 支持记录、搜索、基于想法启动新会话（存入全局 `ideas` 表）。
16. 研究阶段受研究预算约束（普通 2 轮、快速 1 轮，每轮搜索 ≤ 2 次），达到上限自动收敛，不无限研究。
17. 普通模式 review 阶段展示软性内容诊断建议（文字洁癖/表达效率/认知落差），不阻塞导出。

## 7. 后续事项

热点筛选、其他平台、主题编辑器、主题导入/导出命令、更多输入格式、会话删除、复杂搜索优化和高级发布能力后续单独讨论，不进入本 MVP。

## 8. 待评估 feature（不在 MVP）

- **作者档案自动记忆**：从审查反馈中自动识别用户偏好并写入作者档案（类似 Hermes agent 的 memory 机制）。MVP 只做手动 `/profile` 维护；自动识别暂不调研、不实现，作为后续 feature 跟踪。5.4 的质量遥测（尤其是拒绝反馈分类）可作为自动记忆的训练原料。
