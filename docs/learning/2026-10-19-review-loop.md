# 项目与学习复盘规则

- 日期：2026-10-19
- 状态：采用
- 适用范围：写作 Agent 项目实践、Agent 工程学习及双方协作
- 关联计划：`docs/plan/00-plan.md`
- 关联决策：`docs/adr/0010-learning-first-incremental-validation.md`

## 目标

复盘不是工作流水账，而是用证据找出预期与实际的差距，把原因变成下一轮可执行、可验证的改进。目标是减少重复犯错，逐步提高需求分析、设计、实现、验证和学习迁移能力。

## 触发时点

1. **阶段结束**：实施计划中的一个小阶段、一个明确设计任务或一次重要验证达到完成条件时，进行阶段复盘，并在下一阶段开始前回看上次行动。
2. **每周检查**：每周第一次项目工作会话检查上次复盘和本周变化。若本周已经做过阶段复盘，只补充跨阶段问题、反复出现的问题和行动效果，不重写同一批事件。
3. **问题后即时复盘**：发生明显返工、重要设计遗漏、验证误判、重复故障或协作偏差时，可以当场记录，不必等阶段或周末。

助手在当前项目对话中检查是否触发，并主动提出复盘。助手无法在用户没有打开对话时后台发送定时通知；因此“每周提醒”指每周第一次项目工作会话中的检查，不承诺推送通知。用户也可以直接说“复盘”发起。

## 复盘步骤

1. **确定范围**：写清本次阶段或周期的目标、原定完成条件和时间范围。
2. **整理证据**：对照需求、设计、差异、测试/运行输出、错误、决定和学习记录。区分已确认事实、推断和未知；助手自身的误解、漏查或表述不准确也纳入协作复盘。
3. **描述差距**：按“现状 / 问题 / 影响”说明实际结果与预期的差异，不用“做得不够好”代替具体问题。
4. **查原因**：继续追到可改的原因，归入需求、设计、实现、验证、运行或协作/学习方法。证据不足时写“假设”或“待验证”，不把猜测写成根因。
5. **提炼经验**：每次最多保留 3 条。经验要能迁移到下一阶段，写成“遇到什么条件时，采取什么做法，如何判断有效”，避免只写口号。
6. **形成行动**：每条经验对应具体改动或待验证动作，并写明执行时点、验证方法和回看条件。没有可执行动作的观察先登记为待验证，不包装成决策。
7. **回看效果**：下一阶段开始或下一周检查上次行动是否执行、证据是否支持预期效果。无效时调整方案；有效时保留为项目约定或稳定做法。

```markdown

- 日期：YYYY-MM-DD
- 范围：<本次覆盖的阶段、任务或日期>
- 目标：<当时希望达成什么>

## 证据
- <证据名称和路径/命令/结果；没有证据的内容标为假设>

## 差距与影响
- 现状：
- 问题：
- 影响：

## 原因判断
- <原因、归属环节、证据依据和置信度；未知项明确标注>

## 可迁移经验
1. <条件 → 做法 → 有效判据>

## 下一步行动
- [ ] <动作；执行时点；验证方法>

## 回看
- 日期/触发点：
- 结果：待回看
```

## 两个工作区的双向联动

两个工作区通过固定路径读取彼此的当前事实，不复制对方的详细记录：

- 写作 Agent 项目：`/Users/yuanxj/Documents/working/my-write-agent/`。当前阶段与待办看 `docs/plan/00-plan.md`；项目复盘规则和近期经验看 `docs/learning/`，重点入口为本文件。
- Agent 学习工作区：`/Users/yuanxj/Documents/knowledge-space/learn-agent/agent-learning/`。学习状态以 `progress/PROGRESS.md` 为准；课程边界看 `progress/LESSONS.md`；答题和证据细节看 `progress/LOGBOOK.md`。

项目会话联动：开始新的项目阶段、实施或复盘时，检查学习工作区的 `PROGRESS.md` 中“下一个动作”和“待稳定”项，以及最近的 `LOGBOOK.md` 记录；据此选择本阶段的学习目标。项目结束或复盘时，把可用于学习的场景、设计问题和验证证据整理为学习建议，并链接到项目复盘，不把尚未答题/验证的内容写成掌握结果。

学习会话联动：选择学习主题时，检查项目计划当前阶段和待解决设计问题；优先把正在学习的概念用于写作 Agent 的具体设计或故障场景。学习结束时，只有实际完成口述、答题、代码阅读或运行验证，才更新学习工作区；若证据来自项目实践，在学习记录中附项目复盘或代码/运行证据路径。发现项目设计需要调整时，在项目工作区记录，不把架构决策只写进学习日志。

记录分工：项目设计、实现、验证和协作复盘写入 `docs/learning/`；Agent 理论掌握、答题评分、错题和学习状态的唯一记录位置是学习工作区的 `PROGRESS.md`、`LESSONS.md`、`LOGBOOK.md`。通过相对或绝对路径互相引用，避免两边重复维护同一事实。学习工作区历史由用户维护；助手依据实际证据提出或执行进度记录，不从项目复盘推断用户已经掌握。

学习侧复测的执行规则以 `agent-learning/AGENTS.md` 第 9–11 条为准：继续学习开场先复测一题，错题按分数滚动，答题不用自造比喻。项目侧只检查到期复测项是否存在，不复制答题记录，也不把复测通过当成项目阶段验收证据。

## 质量检查

- 每条结论能追到证据，或明确标注为假设/待验证。
- 记录的是可以改变的原因，不停在现象或归责。
- 行动足够小，下一阶段能执行，且有可观察的有效判据。
- 下一轮确实回看旧行动；复盘文件不是只增不读的档案。
- 复盘用来学习和改进，不把一次失误直接变成扩大范围或增加复杂度的理由。
